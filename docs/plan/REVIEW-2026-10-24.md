## Dependency research and remaining uncertainty

- [Envoy.Grpc 1.0.1](https://www.nuget.org/packages/Envoy.Grpc) is a real C# generated-binding package, but the listing's September 2020 update does not establish compatibility with the new schema baseline.
- [ahmelsayed/envoy-csharp-control-plane](https://github.com/ahmelsayed/envoy-csharp-control-plane) documents a Java-inspired C# implementation. It is a reference candidate, not an established substitute for the current Go feature matrix; no current build/parity audit was performed.
- [Buf NuGet SDKs](https://buf.build/docs/bsr/generated-sdks/nuget/) provide an alternative binding-distribution mechanism. Exact Envoy SDK coverage, version alignment, authentication/restore requirements, and package consumption remain unverified.
- The user included optional schema validation. Protovalidate remains a candidate implementation of the pinned PGV semantics. Original metadata preservation and bounded T03 feasibility are required before binding freeze; full equivalence and rule coverage are gated separately by GV. See the [validation plan](../architecture/VALIDATION.md). No runtime selection or conformance result is established by this review.
- [Protobuf documentation](https://protobuf.dev/programming-guides/serialization-not-canonical/) explicitly separates deterministic and canonical serialization. Exact Go/C# hash equality needs evidence if consumers require it.
- [Microsoft's current support table](https://dotnet.microsoft.com/en-us/platform/support/policy) favors .NET 10 for this new runtime library: support through November 2028, versus November 2026 for .NET 8 and 9.
- The rate-limit generated inputs' original schema revision is not recorded by the checkout. Resolve this during the binding proof; do not assume envoy/COMMIT identifies every schema in every module.

## Detailed design follow-through

The [architecture](../architecture/ARCHITECTURE.md) and [decision register](../architecture/DECISIONS.md) now define package/contracts, ownership, per-mode state transitions, cache algorithms, callback failure policy, host lifecycle, and provenance. The [implementation plan](IMPLEMENTATION-PLAN.md) decomposes this into numbered tasks/subtasks with dependencies and acceptance criteria; [traceability](TRACEABILITY.md) maps requirements to verification and release gates.

Additional source inspection makes two boundaries explicit: periodic SnapshotCache heartbeats scan SotW watches, and the Delta loop updates returned-resource tracking on sends without SotW-style stale-nonce rejection or a separate ACK commit stage. The plan preserves those behaviors and calls out divergences for review.
