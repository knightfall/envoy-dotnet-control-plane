## Implementation and boundaries

- `SnapshotCache.FetchAsync` hashes the node, returns all resources for an empty name list or literal exact names in request order (including duplicates), and ignores missing names. Wildcards/prefixes and streaming full-state/ADS readiness rules do not alter Fetch. Missing snapshots throw `KeyNotFoundException`; equal opaque versions throw `SkipFetchException`. Missing types use the empty version. Polling creates no status, watch or request timestamp.
- Responses retain original request/context and stable selected entries, serialize lazily, use normal SotW TTL wrappers and expose an empty returned-resource map for the source's absent ledger. As in the source, an already-canceled immediate cache read can succeed; application hooks/producers can observe cancellation.
- `FetchServer` invokes request hook → producer → materialization → response hook. Hooks can mutate requests/responses. Request/producer failure and missing outer envelopes stop before the response hook. Materialization failure still invokes it with null, then rethrows the original exception. The response hook has no cancellation/context parameter, matching the source signature.
- Eight standard generated services and rate-limit Fetch use that engine. Each adapter overrides type before the request hook. Rate-limit adds dedicated SotW streaming, with no dedicated Delta method. The endpoint inventory is exactly ten SotW, eleven Delta and nine unary methods across twelve services; no ADS/VHDS/LEDS Fetch method is invented.
- Hosting chooses an explicitly registered `IConfigFetcher`, otherwise the watcher when it supplies that capability. A small unsupported producer preserves watch-only hosting. LinearCache's unsupported Fetch and Mux's routing/error behavior remain visible. No application cache/channel is disposed by adapters.
- `MapEnvoyControlPlaneHttpGateway` is separately opt-in and returns ordinary endpoint conventions. A fallback endpoint cleans paths before selecting exactly eight source routes; ordinary application routes take precedence. It overrides body type and uses the same FetchServer. Stock Google.Protobuf parses/formats JSON, preserving proto field names. Defaults register standard resource roots, descriptor dependencies and discovery TTL wrappers; opaque extension Any types require an application-supplied complete registry.
- HTTP success is 200, ordinary wrapped/unwrapped SkipFetchException is empty 304, body read/parse failure 400, unknown route 404, and Fetch/materialization/format errors 500. Error bodies are empty. All HTTP methods are accepted by this handler and content type does not select a codec. The gateway introduces no host quota or parser-limit override.

Kestrel, clients and middleware can normalize/escape URLs before `Request.Path`; source-style slash/dot cleaning applies to the path received by the handler. Existing host body limits, authorization and connection/cancellation behavior remain active. A host may end a connection before the handler can send a status; a read exception reaching this handler maps to 400. Success explicitly uses `application/json`; server exception details remain in debug logs. UTF-8 is decoded strictly. Runtime recursion/numeric limits, JSON byte formatting/property order, exception text and TimeSpan's 100 ns resolution remain runtime/adapter boundaries. The comparison corpus establishes semantic JSON equivalence for the declared cases, not exhaustive cross-runtime parser equivalence.
