# Independent resource/snapshot comparison

See [upstream test reuse](UPSTREAM-TESTS.md) for directly imported code, attributed fixture/scenario adaptations and why source retrieval uses the existing pinned Go module.

`GoOracle/` uses the upstream cache at commit `67c5345367582741334e34ffc66a561b0ce32946`. Its root and Envoy modules are pinned to pseudo-versions ending in `67c534536758`; `ResourceVerification` rejects replacements or revisions that differ from the repository baseline. `go.sum` records dependencies. Use the Go toolchain selected by the repository source lock.

The Core suite reads `tests/Envoy.ControlPlane.Tests/Fixtures/snapshot-cases.json`. These 19 fixtures declare names, versions and consistency outcomes. It exports original protobuf wire payloads, optional TTL nanoseconds and the observed .NET outcomes to its output directory. The Go executable reconstructs the messages and invokes `NewSnapshotWithTTLs`, `Consistent`, resource access and explicit version-map construction. Differences fail the command. The report must contain every declared fixture exactly once.

Run the complete comparison through `dotnet run --project tools/Envoy.ControlPlane.Tools -- repository verify` after binding generation. The Go result is saved under Protocol's `obj/upstream/results/resources/go-results.json` and uploaded with CI evidence. The command uses `-mod=readonly`; it does not alter an upstream checkout.

Coverage includes absent/empty/partial groups, duplicate names, absent/zero/nonzero TTLs, invalid-but-unvalidated messages, EDS service overrides and missing/extra resources, RDS normal/default/standalone chains, and scoped routes including an empty referenced name. The oracle also rejects an unknown built-in snapshot type and checks lazy version-map availability and SHA256 shape. It does not assert cross-language literal hash equality or replace the focused deterministic-byte/hash tests. .NET TTL fixtures use values representable by `TimeSpan` (100 ns precision).

T07 adds `cache.go` to the same pinned Go module. `go run -mod=readonly . cache <candidate-report> <output>` executes 22 SotW cache traces from `cache-cases.json`; the repository command runs it after verifying both Go module revisions. Each trace creates one watch using a capacity-one channel, matching the normal upstream SotW consumer, then publishes, cancels or clears as declared. Response names preserve duplicate multiplicity while sorting unspecified resource order. Type versions, returned versions, snapshot presence and indexed watch counts compare exactly. Cancellation is represented as consumer cancellation in the report; it does not claim Go closes its response channel. Reports are under `obj/upstream/results/cache/` and join existing CI evidence.

The traces establish the direction of ADS snapshot coverage, same-version full/partial state, retained metadata, prefix-only behavior, wildcard/exact overlap, canceled registrations and cleared-but-pending watches. Application clocks and custom snapshots/materialization faults have separate native tests. This capacity-one cache corpus does not represent unbuffered Go-channel blocking/deadline behavior. T10 adds separate channel backpressure and ordered ADS evidence.

T08 adds the `subscription` command in the same pinned module. It invokes actual `config.NewOpts`, legacy-wildcard option functions and `stream.NewSotwSubscription`/subscription methods for all 14 declared traces. Every state compares wildcard mode, exact names, prefix keys and returned versions. The repository CLI validates trace membership and writes Go results under `obj/upstream/results/subscriptions/`. The obsolete-response predicate is private in the source server and has separate native tests; actual stream integration is deferred. Mutable map aliasing is not claimed: .NET accepts read-only metadata and copies it into the stream's own bookkeeping.

T09 adds `stream` to the same pinned module. It drives actual `sotw.NewServer(...).StreamHandler` using controlled request/response handoffs and compares all six declared traces against the native Core observations. Events cover normalized callback inputs, watch/subscription metadata, current-watch nonce replacement, response callback/send order, NACK version retention and cleanup. Every watch is released once in these traces. Input receive failure ends normally, matching the source reader. The driver supplies transport and cache fixtures; it does not reimplement the source processing loop. `repository verify` checks fixture membership and writes Go results under `obj/upstream/results/streams/`. Ordered ADS and network interoperability remain separate.

T21 expands the cache corpus to 23 and stream corpus to 22 traces. The cache driver retains the actual response and reads it again after replacement publication; it does not merely reuse a prior observation. The stream driver writes actual Go events and error/watch lifecycle results, then the repository CLI compares those reports with a stream-wide nonce bijection. Caller versions and literal stale/callback tokens stay exact. The CLI also requires rejection of an injected stale request associated with the current response. Reports include `streams/comparison.json` with source pins and matched IDs. See [T21 preview evidence](../../docs/plan/T21-PREVIEW-DIFFERENTIAL.md) for the exact mapping and remaining proof gates.

T15 adds `linear-cache` in the same pinned module. Thirty-one declared cases call actual upstream LinearCache construction, single/bulk/delete/replace operations and SotW/Delta watches. The comparison checks payloads, counter/hash metadata, removals, readiness and index/resource counts; it observes counts before cancellation and documents the intentional .NET idempotent-disposal difference separately. `repository verify` retains its Go report under `obj/upstream/results/linear-cache/`. No cache algorithm is duplicated in the driver.

T16 adds `mux-cache` in the same pinned module. Its twelve cases instantiate actual `cache.MuxCache` with real Snapshot/Linear children and a small custom Fetch fixture, then compare classifier calls, selected/unselected watch counts, cancellation, responses and known error outcomes. The driver reuses existing message/response shapes and contains no routing algorithm. `repository verify` retains reports under `obj/upstream/results/mux-cache/`. .NET's fixed routing table and watcher-only Fetch capability boundary are documented separately in the native evidence.
